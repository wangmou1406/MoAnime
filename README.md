# 动漫下载机 · Anime Downloader

Python + Flask 重写的动漫下载软件（Web 界面），参考了
[XiaoMoAnime](https://github.com/196632094/XiaoMoAnime) 的使用方式，
但整体架构重做：**所有动漫源都可以在网页上添加、拖拽排序、勾选启用**，不需要改代码。
**首次启动即内置 14 个实测可用的动漫源，装好就能直接搜、直接下。**

## 一、内置动漫源（开箱可用）

首次启动会自动写入 **13 个 MacCMS 资源站接口源**，其中 10 个**默认启用**、实测可直接给出 m3u8：

| 启用 | 源 | 类型 | 说明 |
| --- | --- | --- | --- |
| ✅ | 量子资源 | maccms | 实测直链 m3u8，剧集完整 |
| ✅ | 暴风资源 | maccms | 实测直链 m3u8，剧集命名规整 |
| ✅ | 最大资源 / 无尽资源 / 虎牙资源 / 金鹰资源 | maccms | 实测直链 m3u8 |
| ✅ | 飘零资源 / 360资源 / 魔都资源 / 百度资源 | maccms | 实测直链 m3u8 |
| ⬜ | 极速资源 / 红牛资源 | maccms | 首集是分享页，下载时程序会自动进页面解析 m3u8 |
| ⬜ | 非凡资源 | maccms | 同上，稳定性略低 |

这些接口是苹果 CMS(v10) 资源站对外提供的采集接口，`vod_play_url` 字段里**直接带每一集的 m3u8**，
所以「检索 → 剧集 → 下载」全程无需逆向、无需浏览器。

删掉 `data/moanime.db` 后重启会自动重新补齐内置源（不会覆盖你改过的同名源）；
某个接口失效时，在「动漫源」页取消勾选即可，不影响其它源。
源配置可整体「导出」成 JSON 备份或分享，也能「导入」别人的配置。

> 想接入**网页型**动漫站（非资源接口）时，用「添加源 → 通用可配置源」或「自动探测」，
> 见第五节。

## 二、快速开始

### 方式 1：双击 `启动.bat`（推荐）
启动器会自动完成：检测可用的 Python → 使用/创建 `.venv` → 安装依赖 → 启动服务 → 打开浏览器。
**不要求**你先装好 Python 或配置 PATH：只要 `.venv` 目录存在就直接复用它。
**这个黑窗口要一直开着**，关掉窗口 = 停止服务。

### 方式 2：后台常驻（关掉窗口也继续跑）
```powershell
powershell -ExecutionPolicy Bypass -File .\后台启动.ps1   # 后台启动（隐藏窗口）
powershell -ExecutionPolicy Bypass -File .\停止.ps1       # 停止服务
```
后台模式的日志写到 `logs/service.err.log`；`停止.ps1` 会先确认端口上的进程确实是 MoAnime
（按命令行判断），再结束它。

### 方式 3：PowerShell 启动器（前台）
```powershell
powershell -ExecutionPolicy Bypass -File .\launcher.ps1
powershell -ExecutionPolicy Bypass -File .\launcher.ps1 --port 9000 --no-browser
```

### 方式 4：直接用虚拟环境的解释器
```powershell
cd "C:\Users\luoji\Desktop\项目文件\DeepSeek Harness\软件\MoAnime"
.\.venv\Scripts\python.exe run.py            # 默认 http://127.0.0.1:8848
.\.venv\Scripts\python.exe run.py --port 9000 --no-browser
.\.venv\Scripts\python.exe run.py --host 0.0.0.0     # 局域网访问
```

启动后在「检索」页输入片名（例如 `海贼`）回车，挑一个源里的条目 → 勾选剧集 → 下载即可。

程序**零配置即可用**：内置 13 个资源接口源（10 个默认启用），打开就能检索、看剧集、直接下载。

### 方式 5：Docker（镜像已内置 ffmpeg + Chromium 内核）

镜像基于 `python:3.12-slim`，**开箱自带三样东西**，宿主机不需要装任何依赖：

| 内置内容 | 版本（实测构建） | 用途 |
| --- | --- | --- |
| **ffmpeg** | 7.1.5（Debian trixie） | m3u8 分片 → mp4 转封装 |
| **Chromium** | 156.0.8078.4（Playwright 构建） | 「浏览器取流」执行站点 JS 抓真实视频地址 |
| **Node.js** | 22.11.0（官方 Linux 包） | 驱动上面的 Chromium（`player_sniffer.js`） |

内核与 Node 装在镜像内的 `/opt/pwt`，**不放在 `/app/data`** —— 因为 `data/` 在容器里是挂载卷，
放进去会被卷遮住。程序通过 `AD_BUNDLED_DIR=/opt/pwt` 找到它们
（`core/browser_resolver.py` 会识别成「内置内核」）。

```bash
# 一条命令起（数据落在当前目录）
docker compose up -d --build

# 或者不用 compose
docker build -t anime-downloader:latest .
docker run -d --name anime-downloader \
  -p 8848:8848 \
  -v "$PWD/docker-data:/data" \
  -v "$PWD/downloads:/downloads" \
  -v /dev/shm:/dev/shm \
  --restart unless-stopped \
  anime-downloader:latest
```

打开 <http://localhost:8848> 即可。常用命令：

```bash
docker compose logs -f          # 看日志
docker compose restart          # 重启
docker compose down             # 停止并删除容器（数据在挂卷里，不会丢）
docker compose up -d --build    # 改完代码重新构建
```

**国内加速**：Chromium 走 Playwright 官方 CDN，国内可能很慢（实测 50 分钟只走完 20%）。
换成镜像源后约 36 秒：

```bash
docker compose build --build-arg PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright
# 或写进 docker-compose.yml 的 build.args（文件里已有注释掉的示例）
```

**下载路径怎么改（三种方式，任选一种）**

`docker-compose.yml` 里的挂载已经全部变量化，不用改 yaml 的正文：

```yaml
volumes:
  - "${AD_DATA_HOST:-./docker-data}:/data"
  - "${AD_DOWNLOAD_HOST:-./downloads}:${AD_IN_DOWNLOAD:-/downloads}"
```

| 方式 | 做法 | 适合 |
| --- | --- | --- |
| **① `.env`（推荐）** | 把 `.env.example` 复制成 `.env`，改 `AD_DOWNLOAD_HOST=/volume1/video/anime` | 一次配好，长期不动 |
| **② 直接改 yaml 顶部注释处** | 把 `${AD_DOWNLOAD_HOST:-./downloads}` 换成写死的 `/volume1/video/anime` | 只在一台机器上用 |
| **③ 临时覆盖** | `AD_DOWNLOAD_HOST=/mnt/anime docker compose up -d` | 试一下换个位置 |

可用的变量（都有默认值，不设也能跑）：

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `AD_DOWNLOAD_HOST` | `./downloads` | **宿主机**上放视频/字幕的目录，最常改的就是这个 |
| `AD_DATA_HOST` | `./docker-data` | **宿主机**上放数据库/设置/日志的目录 |
| `AD_IN_DOWNLOAD` | `/downloads` | **容器内**的下载目录（只有想改容器内布局时才动） |
| `AD_HOST_PORT` | `8848` | 宿主机映射端口，被占用时改这里 |
| `AD_CONCURRENT_TASKS` | `3` | 同时下载的剧集数 |
| `AD_SEGMENT_THREADS` | `8` | 单任务分片并发 |
| `AD_LOG_LEVEL` | `INFO` | 日志级别 |
| `AD_THEME` | `light` | 界面主题 |

> **改了路径要重建容器**：`docker compose up -d`（不用 `--build`，只重建容器）。
>
> **临时目录会自动跟随**：compose/Dockerfile 都**刻意不设** `AD_TEMP_DIR`，
> 程序会把分片临时目录算成 `<下载目录>/.tmp`。所以只改 `AD_DOWNLOAD_DIR` 一处就够了。
> 实测：把容器内下载目录设成 `/media/anime` 时，分片确实落在
> `/media/anime/.tmp/<番剧>_<集>/`，`/downloads` 完全没用到。

**挂卷约定**（两个目录都是 VOLUME，建议都挂出来）：

| 容器内路径 | 内容 | 说明 |
| --- | --- | --- |
| `/data` | 数据库、`settings.json`、日志、预览图缓存 | 不挂的话重启就丢配置 |
| `/downloads` | 下载好的视频与字幕 | 用 `AD_DOWNLOAD_HOST` / `AD_IN_DOWNLOAD` 改宿主机或容器内路径 |

> ⚠️ **和本机版同时跑会抢 8848 端口**。容器默认也绑 8848，
> 如果你本地 Windows 服务也在跑，两个都会"启动成功"但请求会串。
> 同时用的话给容器换个端口：`.env` 里设 `AD_HOST_PORT=18848`。

**环境变量**（优先级高于界面里的设置，容器部署建议只用环境变量）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `AD_HOST` | `0.0.0.0` | 容器里必须监听 0.0.0.0，否则外面访问不到 |
| `AD_PORT` | `8848` | 监听端口 |
| `AD_DATA_DIR` | `/data` | 数据目录 |
| `AD_LOG_DIR` | `/data/logs` | 日志目录 |
| `AD_DOWNLOAD_DIR` | `/downloads` | 下载目录 |
| `AD_TEMP_DIR` | `/downloads/.tmp` | 分片临时目录（不设则自动跟随下载目录） |
| `AD_BUNDLED_DIR` | `/opt/pwt` | 内置内核与 Node 的位置（改这里就能换内核目录） |
| `AD_PLAYWRIGHT_DIR` | `/opt/pwt/node_modules/playwright-core` | playwright-core 位置 |
| `AD_SNIFFER_TMP` | `/tmp/sniffer` | 嗅探器放浏览器 profile 的临时目录 |
| `AD_CONCURRENT_TASKS` | `3` | 同时下载的剧集数 |
| `AD_SEGMENT_THREADS` | `8` | 单个任务的分片并发 |
| `AD_LOG_LEVEL` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |
| `AD_THEME` | `light` | `light` / `dark` |
| `AD_PROXY` | 空 | 需要走代理时填，例如 `http://host.docker.internal:7890` |

镜像里已经处理好的细节：

* **ffmpeg 走系统 PATH**：查找逻辑按平台选 `ffmpeg` / `ffmpeg.exe`，
  Windows 的 `tools/ffmpeg.exe` 在 `.dockerignore` 里被排除，不会被误用；
* **界面上的「一键安装 ffmpeg」在非 Windows 返回明确提示**（那个按钮下载的是 Windows 版），
  容器里本来就已装好，不会误触发下载；
* **中文字体已装**（`fonts-noto-cjk`）：浏览器渲染中文页面不会变成方块；
  文字广告体检的 OCR 自检也要用字体画测试图（没字体会明确报「没找到可用字体」，不会误报 OCR 坏）；
* **Chromium 运行库齐全**（`libnss3`/`libatk*`/`libgbm1`/`libcups2`/`libasound2` 等），
  启动参数已带 `--no-sandbox --disable-dev-shm-usage`；
* **非 root 运行**（用户 `anime`，UID 1000），下载与写库都在挂卷里进行；
* 带 `HEALTHCHECK`，`docker compose ps` 能看到健康状态；
* `.dockerignore` 排除了 `data/`、`logs/`、`downloads/`、`.venv/`、`tools/ffmpeg.exe`，
  **镜像里不会夹带你的数据库、已下载视频，以及那 500MB 的 Windows 版内核**。

### 界面

布局参考 XiaoMoAnime：**浅色底 + 顶部居中标题 + 横向标签页 + 卡片式内容**，六个标签页：

| 标签 | 内容 |
| --- | --- |
| 番剧搜索 | 检索栏（检索方式下拉 + 关键字 + 搜索）、参与检索的源（勾选胶囊 + 优先级序号）、结果列表（封面/集数/是否直链可下载）、剧集面板 |
| 动漫源 | 源列表：拖动手柄调整优先级、勾选框控制是否参与检索、信号灯（绿=正常/橙=有报错/灰=未测）、测试/测活/编辑/复制/删除 |
| 下载任务 | 统计条（进行中/暂停/完成/失败/总大小/实时速度）+ 任务列表（进度条、分片数、暂停/继续/重试/删除）；**按番剧分组**，每个分组头有 `暂停全部` / `继续全部` / `删除全部` |
| 番剧库 | 扫描下载目录，按动漫折叠展开，逐集预览或删除 |
| 设置 | 下载位置、命名规则、并发与网络、后处理、界面与服务、外部依赖（ffmpeg）、维护工具 |
| 系统日志 | 实时日志流（级别过滤、自动滚动、清空）；**按等级上色**（INFO 蓝 / WARNING 琥珀 / ERROR 红），
警告与错误行还有整行底色，正文里的集数、大小、路径会高亮，窗口高度占满剩余屏幕 |

顶层状态栏还有一条实时线：当前标签、启用源数、任务数、实时速度、连接状态、版本与**前端构建号**（用于确认页面是否最新）、`STANDBY/DOWNLOADING`。

#### 分组头：暂停全部 / 继续全部 / 删除全部

下载任务按**番剧分组**（每部动漫一个分组，带集数、状态汇总、总大小、总进度）。
每个分组头右侧有三个按钮，一次操作整部番剧：

| 按钮 | 作用 | 影响范围 |
| --- | --- | --- |
| **暂停全部** | 暂停该番剧所有 **运行中 / 排队** 的任务 | 已完成/失败的不动 |
| **继续全部** | 继续该番剧所有 **已暂停** 的任务 | 同样不影响其它状态 |
| **全部重试** | 重新提交该番剧所有 **失败 / 已取消** 的任务 | 已完成/进行中的不动；会**重新解析视频地址**后再排队 |
| **删除全部** | 删除该番剧的**全部下载记录** | ⚠️ 可选是否连文件一起删，见下 |

顶部工具栏也有对应的 全部继续 / 全部暂停 / 全部重试 / 全部删除（作用于所有番剧）。

> 全部重试 只处理 失败 与 已取消 两种状态 —— 这是后端 
etry() 的硬性前提。
> 逐条容错：某条重试失败不会影响其它条，最后提示「已重新提交 N 个任务，M 个跳过」。
> 因为视频地址通常带时效，重试会**重新解析地址**而不是复用旧链接。

#### 删除时可选「同时删除文件」

点 删除全部（或任务行右侧的 🗑、顶部的「删除全部」）会弹出删除确认框：

`
删除下载记录
────────────────────────────────
狐妖小红娘 · 103 条下载记录
其中 73 个正在下载/排队，会先被取消。

☐ 同时删除已下载的视频文件（33 个有文件路径，约 4.4 GB）

                          [取消] [删除记录]
`

| 勾选框 | 效果 | 按钮文案 |
| --- | --- | --- |
| **不勾**（默认） | 只删任务记录，磁盘上的 mp4 **原样保留** | 删除记录 |
| **勾上** | 连记录里 save_path 指向的文件一起删 | 删除记录和文件 |

细节：

* 默认**不勾** —— 记录删了还能重下，文件删了就没了；
* 点中勾选框会实时出现红色警告「视频文件会被永久删除，不进回收站，无法恢复」；
* 勾选框上方会显示**有多少条记录带文件路径、合计多大**，方便判断影响面；
* 如果这些记录都还没有文件（save_path 为空），勾选框会**自动禁用**并提示；
* 文件不存在时跳过，不报错；
* 三处删除（分组头 / 任务行 / 顶部「删除全部」）**都用同一个确认框**，行为一致。

> 分组的**收起/展开**状态会记住，刷新页面不会弹回。

### 清除用户配置（恢复出厂）

「设置 · 维护」里有一个红色的 **清除用户配置（恢复出厂）** 按钮，需要**两次确认**
（先确认清单，再手动输入 `RESET`）。

清掉的内容：

| 项目 | 说明 |
| --- | --- |
| 全部设置项 | 下载目录、并发、命名、**外观自定义**等一律回到默认值 |
| 全部任务记录 | 任务列表清空（含排队/暂停/完成/失败） |
| 下载历史、检索历史 | 数据库里的 history / search_history 表清空 |
| 自定义背景图、预览图缓存 | `data/backgrounds/`、`data/thumbs/` 清空 |
| 下载残留的临时分片 | `downloads/.tmp/` 清空 |
| 源的「含广告」标记 | 源本身保留，只是标记与顺序恢复默认 |
| 系统日志 | 一并清空 |

**不会删除**已经下载好的视频文件——下载目录默认就在项目内的 `downloads/`，
重置后路径不变，文件原地不受影响（实测重置后 21 个 mp4 / 1075 MB 完好）。

### 外观自定义（深色模式 / 配色 / 背景 / 标题 / 动效）

全部在 **设置 → 外观自定义**，改完点「保存设置」；大部分项改了会**当场预演**，不用先保存。

#### 配色方案（一键换色）

7 套预设，每套给出 3 个底色 + 1 个主色（色板卡上直接能看出效果）：

| 方案 | 特点 |
| --- | --- |
| 跟随主题 | 不覆盖任何颜色，完全由亮色/暗色主题决定 |
| 墨蓝 | 深色页面 + 更深面板，接近 IDE/终端观感 |
| 纸白 | 亮色高对比，卡片纯白 |
| 暖褐 | 低蓝光暖色，长时间盯任务更舒服 |
| 松绿 | 绿色主色 + 浅灰绿底 |
| 夜紫 | 深紫底 + 紫色主色，暗环境对比柔和 |
| 高对比 | 纯黑底，户外/投影更清楚 |

套用后仍可**逐项微调**，改动手动颜色后会自动标记为「自定义」。

#### 页面颜色（4 项，可单独改）

| 项 | 影响范围 | 留空时 |
| --- | --- | --- |
| 页面主色 | 按钮、选中态、进度条、链接 | 跟随主题（蓝） |
| 页面底色 | 整页背景 | 跟随主题 |
| 卡片/面板底色 | 卡片、弹窗、侧边栏 | 跟随主题 |
| 次级底色 | 表头、统计格、日志框 | 跟随主题 |

每项都有一个取色器、一个文本框（可填 `#2563eb` / `red`）、**6 个快捷色块**和一个「✕」清除按钮。

> **文字色会自动补偿**：只改底色不改文字，会出现「深色底 + 深色字 = 全看不清」。
> 所以程序按底色的**相对亮度**判断深浅（阈值 0.35），自动切换一套文字/描边色。
> 实测夜紫方案下正文对比度 ≈15:1、次要文字 ≈8:1，都远超 WCAG AA 的 4.5:1。
> 四个颜色都留空时不接管文字色，交回主题决定，避免固定值破坏主题对比。

#### 界面动效（三档）

| 档位 | 表现 |
| --- | --- |
| **全部**（默认） | 保留所有动效 |
| **仅状态** | 保留**能说明"正在跑"**的动效：进度条流光、状态点呼吸、骨架脉冲、转圈；去掉进场/悬停/弹跳这类装饰性动画 |
| **关闭** | 全部静止（`animation` 与 `transition` 都停） |

实测三档对同一批元素的效果：

| 元素 | 全部 | 仅状态 | 关闭 |
| --- | --- | --- | --- |
| 任务行/结果行入场 | `ad-enter` | none | none |
| 进度条流光 | `ad-shimmer` | **`ad-shimmer`** | none |
| 状态点呼吸 | `ad-led-breathe` | **`ad-led-breathe`** | none |

系统级 `prefers-reduced-motion: reduce` 依然会强制关掉全部动效（与档位叠加生效）。

#### 其它外观项

* **界面主题**：亮色 / 暗色；
* **页面标题**与**标题颜色**；
* **背景图**：拖拽图片、点选本地文件，或填 http(s) 地址；
* **背景模糊 / 遮罩 / 面板不透明度 / 填充方式**。

> 全部通过 `<html>` 上的 CSS 变量下发，不注入内联 `<style>`。
> 同时会把当前外观缓存进 `localStorage`，刷新时在样式表加载后**立刻套用**，
> 避免先亮一下再变暗的闪屏。

顶栏右侧还有一个 🌙/☀️ **快捷开关**，点一下立即切换主题并保存。
背景图支持 jpg/png/webp/gif/bmp，上限 8 MB；带缩略图预览与「清除背景图」。

实现细节与安全处理：

* 背景图**按魔术字节**判断真实格式（不信任前端传来的后缀名），非图片内容直接拒绝；
* 文件名由服务端生成（`bg_<时间戳>_<哈希>.png`），写入 `data/backgrounds/`；
  上传新的会自动清掉旧的，不会越积越多；读取接口只允许访问该目录内的文件（**目录穿越已实测拦截**）；
* 外观通过 `<html>` 上的 **CSS 变量**下发（`--app-bg-image` / `--app-bg-blur` / `--app-bg-dim`
  / `--panel-alpha` / `--app-title-color`），不注入内联 `<style>`，避免样式被乱写；
* 主题与背景会缓存到 `localStorage`，**刷新时在样式表加载后立刻套用，不会闪一下亮色**；
* 面板半透明用 `color-mix()`，不支持的浏览器自动退回不透明（`@supports` 兜底），保证可读性。

### 在线预览播放（不下载先看）

每行剧集有两个按钮：**▶ 在线播放** 和 **🖼 预览图**。点 ▶ 会弹出播放器**直接串流播放**，
不用等下载完：

```
[模态播放器]  贤惠幼妻仙狐小姐 · 第05集          [🔗复制直链] [⬇加入下载]
   ┌──────────────────────────────────────────────┐
   │              （视频画面，可播放/拖动/全屏）        │
   └──────────────────────────────────────────────┘
   /api/video/stream?url=...        [3 档清晰度]
```

* **原理**：站点的视频都是 HLS（m3u8）。浏览器原生播不了 m3u8（Safari 除外），
  所以本地化了 **hls.js**（`static/vendor/hls.min.js`），完全离线可用；
* **关键难点——跨域**：视频站的分片不允许跨域，浏览器直接拉会被 CORS 拦。程序加了
  服务端代理 `/api/video/stream`：拉取远程内容 → **重写播放列表里的所有地址**
  （含 `#EXT-X-KEY` 的密钥 URI、子列表、分片）→ 回传给前端，
  并透传 `Range` 请求头以支持拖动进度；
* **清晰度**：m3u8 里有多档码率时，播放器会显示档位数，hls.js 会自动选流并可手动切换；
* **出错兜底**：网络错误自动 `startLoad()` 重试、解码错误自动 `recoverMediaError()`；
  彻底失败时给出明确提示，并引导用「⬇ 加入下载」后本地播放；
* **附带操作**：🔗 复制视频直链（浏览器剪贴板不可用时退回到弹窗展示）、
  ⬇ 直接把这一集加入下载队列；
* 关闭弹窗会自动**销毁 hls 实例**，不会在后台继续拉流；
* 番剧库 / 任务列表里的「播放」是播放**已下载的本地文件**（走 `/api/library/stream`），
  与在线预览是两个独立入口。

> 实测（服务端链路）：解析地址 → 主播放列表（3 行）→ 子播放列表（1489 行 / 721 个分片）
> → 分片 159 KB、TS 同步字节 `0x47`，全链路可用。
> 浏览器端的实际播放请你在页面上确认（本环境的无头浏览器不执行页面脚本，我无法代你验证这一层）。

### 剧集面板（竖向列表 + 预览图）

点开一部动漫后，剧集以**竖向单列**列出（不再是一堆挤在一起的方形小标签），每行包含：

```
☑   [缩略图]   第01集                                  [🖼]
                第 1 项 · https://.../index.m3u8
☑   [缩略图]   第02集                                  [🖼]
                ...
```

* **缩略图**：用 ffmpeg 抽取该集**第 30 秒**的画面作为预览，一眼就能看出这集是不是
  正片、有没有插广告/花屏；失败时显示占位图标（不会留破图）；
* **单集预览**：点行尾的 🖼 按钮只加载这一集；
* **批量预览**：点「加载全部预览」，限 3 并发逐集加载，右下角作业面板显示进度
  （成功/失败集数），边加载边显示；
* **缓存**：预览图按视频地址哈希缓存在 `data/thumbs/`，同一集再次打开**秒出**
  （实测首次约 12 秒、命中缓存 0.03 秒）；点「清空预览」可清掉当前显示；
* 列表最高 62vh，超出内部滚动，148 集也不会把页面撑得很长；
* 勾选框、反选、下载全部/选中 的行为与之前一致。

### 右下角「后台作业」面板

除了下载任务（那有独立的「下载任务」页），其它耗时操作都会在**右下角**显示实时进度，
不会只丢一个会消失的提示条：

| 显示内容 | 说明 |
| --- | --- |
| 作业标题 | 如「广告体检 · 狐妖小红娘」「全部测活」「聚合检索 · 海贼」「扫描媒体库」 |
| 进度 | `9/13` 计数 + 进度条（进行中蓝色、成功绿色、失败红色） |
| **实时日志** | 带时间戳的滚动日志，如「金鹰资源：命中 9 条（0.97s）」，**每个源一返回就写一行** |
| 结束状态 | 成功的作业变绿并显示结果摘要（命中多少条 / 释放多少空间），失败的变红并写明原因 |
| 保留时间 | 成功后保留 9 秒、失败保留 12 秒再淡出，来得及看清 |
| 头部徽章 | `N 进行中` / `已结束` |
| 清空按钮 | 只清掉已结束的，进行中的保留 |

**看完整日志**：面板里只露最近几行（滚动），**点作业标题**会弹出该作业的完整日志，
适合长任务结束后回看每一步。

已接入的操作：**聚合检索、全部测活、单个源测试、广告体检（逐源实时刷新）、源质量采样、
批量字幕匹配、媒体库扫描、批量加载预览图**。
作业面板出现时，右下角的提示条会自动上移，不会互相遮挡。

> **流式接口**：聚合检索（`/api/search/stream`）和广告体检（`/api/tools/duration-stream`）
> 都是 NDJSON 流，每完成一个源就推一行给前端，所以进度是真实逐源走的，
> 而不是"转圈等十几秒然后一次性出结果"。
>
> 检索的日志会区分三种情况，便于判断问题出在哪：
> `命中 N 条` / `没有匹配结果`（源是好的，只是没这个片名）/ `检索失败`（源真的连不上）。
> 「没有匹配结果」**不计入失败源**，也不会出现在「以下源检索失败」清单里。

主题可切暗色（设置 → 界面与服务 → 界面主题），暗色下布局与信息层级保持一致。

> 小技巧：`http://127.0.0.1:8848/?keyword=海贼` 可直接打开并检索；
> 不带参数时页面会自动恢复上次的检索关键字。也支持 `#sources` / `#tasks` / `#library` / `#settings` / `#logs` 直达标签页。

## 三、动漫源是怎么配置的

一个“源”就是一份 JSON 配置 + 一个类型。`sources/` 下加一个继承 `SourcePlugin` 的类并用
`@register("type")` 装饰，Web 会自动出现该类型。当前有四种：

### 1. MacCMS 资源站接口 `maccms`（内置源用的就是它）
**支持的响应格式（自动识别，不用手选）**：

| 格式 | 路径 | 说明 |
| --- | --- | --- |
| JSON | 默认 / `/at/json` | 主流，直接取 `list[].vod_*` |
| **XML** | **`/at/xml`** | 实为标准 RSS（`<rss><list><video>`），解析后转成与 JSON **同构**的字典 |
| JSONP | `callback({...})` | 自动剥壳 |

XML 的结构是这样的（`<dl><dd flag="线路名">` 里装剧集）：

```xml
<rss version="5.1"><list page="1" recordcount="20"><video>
  <id>21681</id><name><![CDATA[海贼王]]></name><type>日韩动漫</type>
  <pic>https://example.com/a.jpg</pic><note><![CDATA[更新至第1180集]]></note>
  <dl><dd flag="feifan"><![CDATA[第01集$https://cdn/1.m3u8#第02集$https://cdn/2.m3u8]]></dd></dl>
</video></list></rss>
```

同一站往往两种都提供：`cj.ffzyapi.com` 的 JSON 与 `/at/xml/` 返回的是
**同一份数据**（实测番剧名、集数、首集地址完全一致）。加了 XML 支持后，
`电影天堂`、`非凡资源(XML)` 这类只给 XML 的接口才能用。

> 踩坑记录：真实接口的 CDATA 标记是**留在文本里**的。若只还原 HTML 实体
> 而不剥掉 `<![CDATA[` / `]]>`，被 `#` 切开后第一集名会变成 `<![CDATA[第01集`。
> 这个坑已由 `tools/test_xml.py` 盯着（它会拿同一接口的 JSON 与 XML 版对照）。

只需一个接口地址，`vod_play_url` 里直接带每集的 m3u8，最省事，也支持配置多个备用接口自动切换：

```json
{
  "base_url": "https://cj.lziapi.com/api.php/provide/vod/",
  "api": "https://cj.lziapi.com/api.php/provide/vod/",
  "apis": [
    { "name": "备用线路", "api": "https://bfzyapi.com/api.php/provide/vod/" }
  ],
  "request_timeout": 20,
  "test_keyword": ""
}
```
主接口不可用时，会按 `apis` 顺序自动尝试下一个；「测试」按钮会逐个接口报告
「条目数 / 剧集数 / 是否 m3u8 直链 / 具体错误」。

用 CSS 选择器或正则描述“怎么检索、怎么取剧集、怎么取视频地址”：

```json
{
  "base_url": "https://www.example.com",
  "encoding": "",
  "headers": { "Referer": "https://www.example.com" },
  "search": {
```

| 写法 | 含义 |
| --- | --- |

### 浏览器取流（播放器嗅探）· 可选

有些站的视频地址**必须执行站点自己的 JS** 才算得出来：

* **会话签名**：Anime1 的播放器只有 `<video data-apireq="<编码令牌>">`，
  令牌里的时间戳 `t` 与会话签名 `s` 由页面 JS 现场生成 —— 直接 POST 接口返回 **403**；
* **混淆解密**：次元城把地址藏在混淆函数里（字符串数组混淆），**不可能用 Python 复刻**；
* **客户端渲染**：次元城首页只返回 1729 字节空壳，内容全靠 JS 拉。

这些站不是"选择器没配对"，而是**页面上根本没有可解析的内容**。与其逐站逆向，
不如换个思路：

> **不需要知道地址是怎么算出来的 —— 只要看浏览器最终请求了哪个视频地址。**

做法：用无头浏览器打开播放页，**监听网络请求**，截获 `.m3u8` / `.mp4`。
站点 JS 在浏览器里正常执行，我们只在旁边记录结果 —— **不需要为每个站写适配**。

**实测（Anime1）**：

```
搜索「海賊王女」→ 1 部 / 12 集
取流 9.6s → https://chima.v.anime1.me/929/1.mp4
下载  18s → downloads\海賊王女\第01集.mp4
       112.9 MB · H.264 1280x720 · 23:33 · ffmpeg 解码无错误
```

**关键细节：还需要会话 Cookie。** 视频 CDN 校验一个**路径绑定的 JWT**
（`p=eyJ...` 解出来是 `{"sub":"/929/1.mp4",...}`），缺了它**只改 Referer 也没用**
（实测 4 种 Referer 组合全部 403）。所以嗅探器会把浏览器此刻的 Cookie、
User-Agent、播放页 Referer 一并带回来交给下载器复用。

#### 与「Node 桥接」方案的对比

有的同类软件（如 XiaoMoAnime）为**每个站**写一份 Node mock 脚本：把网站的混淆 JS
拿到本地，伪造 `window` / `document` / `jQuery` 后跑出地址。那条路可行，但：

| | Node 桥接（每站一份脚本） | 浏览器嗅探（本程序） |
| --- | --- | --- |
| 单站成本 | **13~56 KB 手工代码** | **0**（一次实现覆盖所有站） |
| 网站改版 | 要重新扒 JS、重写 mock | 无需改动 |
| 依赖 | Node + 每站的 JS 文件 | Node + 一个 Chromium 内核 |
| 局限 | 纯 HTTP，拿不到 MSE/blob | MSE(blob:) 那类也拿不到 |

#### 使用

| 项目 | 说明 |
| --- | --- |
| **开关** | 设置 → 并发与网络 → **浏览器取流（播放器嗅探）**，可随时关闭 |
| 依赖 | **全部内置**：Chromium 内核 + Node.js + `playwright-core` 都已放进 `data/_pwt/`，开箱即用，**不需要你机器上装 Edge 或 Node** |
| 常驻进程 | `tools/player_sniffer.js` 保持一个浏览器实例，通过 stdin/stdout 收发任务 |
| 耗时 | 首次约 10s（要启动浏览器），之后每集约 5s |
| 缓存 | 同一播放页 10 分钟内重复解析直接命中，不重复开浏览器 |
| 影响范围 | **只有声明需要它的源**才走这条路径；普通 HTTP 源完全不受影响 |
| 状态查看 | 设置 → **浏览器取流 · 播放器嗅探** 卡片：就绪时显示「**已就绪 · 内置内核**」与「内置 Chromium · 内置 Node · 缓存 N 条」，可重新检测、清空缓存 |
| 关闭后 | 依赖它的源会给出明确错误（"需要浏览器取流，但当前不可用（已在设置中关闭）"），不会静默失败 |

#### 内置浏览器内核（免安装）

早期版本借用系统已装的 Edge/Chrome，换台机器没装浏览器就用不了。
现在内核随程序一起发布：

```
data/_pwt/
├── browsers/chromium-1248/chrome-win64/chrome.exe   Chromium 内核（约 436 MB）
├── node/node.exe                                     Node 运行时（约 89 MB）
└── node_modules/playwright-core/                     驱动库
```

查找顺序（`core/browser_resolver.py`）：

| 资源 | 顺序 |
| --- | --- |
| 内核 | `AD_BROWSER_PATH` 环境变量 → **内置 Chromium** → 系统 Edge → 系统 Chrome → `PATH` 里的 chromium |
| Node | `AD_NODE_PATH` 环境变量 → **内置 Node** → `PATH` 里的 node → 常见安装路径 |

也就是说**内置的优先**，系统装了也不会乱用；想临时指定别的内核时设环境变量即可。

**实测（内置内核）**：本地放一个页面，`setTimeout` 800ms 后才用 JS 动态插入
`<video src="...m3u8">`，嗅探器正确截获了该地址 —— 证明内核能执行页面 JS 并监听网络。

体积说明：内核约 436 MB。如果不需要浏览器取流（不用 Anime1 这类站），
删掉 `data/_pwt/browsers` 即可，其余功能不受影响。

#### 怎么让自己的源用上它

**通用源**（`generic`）勾选 `video.browser` 即可 —— 它会在"正则抓不到地址"时
自动改用浏览器嗅探：

```json
{
  "video": {
    "type": "auto",
    "patterns": ["\"url\":\"(.*?\\.m3u8.*?)\""],
    "browser": true,
    "sniff_wait": 12000
  }
}
```

顺序是：**先按正则抓（快）→ 抓不到且勾了 browser 才开浏览器（慢但通用）**。

## 四、检索与下载流程
1. **聚合检索**：按源优先级顺序，用 `search_concurrency` 个线程并发请求所有已勾选的源；
   某源连不上或没匹配都会单独标注，不影响其他源。
   **结果按番剧分组**（不是按资源站），见下。
2. **剧集**：点播出单里的条目 → 调该源 `episodes()` → 勾选要下载的集。
   MacCMS 源会直接拿到全部剧集与每集 m3u8。
   **多线路处理**：很多资源站给两条线路，*线路1 常是分享页/播放页（只能看不能下），线路2 才是直链 m3u8*。
   程序会**自动挑选「直链比例最高」的那条线路**，所以不会再把分享页当成下载地址。
3. **下载**：任务进入队列，由 `concurrent_tasks` 个工作线程消费。
   **默认只从你选定的那个源下载**；只有在剧集面板里打开「失败自动换源」后，
   解析不出视频地址时才会自动换其它已启用源重排同一集（最多 3 次），
   界面会显示「已自动换源：XXX（原源 YYY 只能看不能下）」。

### 检索结果按番剧分组

同一部番往往在**多个源**都有，以前按资源站分块展示，同一部番会在 9 个块里各出现一次，
用户得来回找「到底哪个源有这部」。现在以**番剧为主**：

```
01  狐妖小红娘                      8 个源命中        [已合并同名片源]
    01  [封面]  狐妖小红娘
                148 集 · 中国动漫 · 第148话
                [红牛资源] 金鹰资源  无尽资源  量子资源  暴风资源  最大资源 …
                                              ↑ 当前选中的源（蓝底）
    02  狐妖小红娘镜花缘篇           10 个源命中
```

* 每个番剧一个分组，**同名条目合并成一行**，不重复；
* 行内列出「这部在哪些源有」，点某个源标签即**切到该源**（`state.pickedSource`），
  该行数据的 `url`/`source_id` 随之更新，接着点行或点标签都会用这个源打开剧集；
* 源标签按**全局源优先级**排序，第一个为默认选中；
* 分组排序：**片名与关键词完全匹配的在前** → 命中源数多的在前（更可能下得动）→ 按名称；
* 汇总行显示 `命中 N 条 · 合并为 M 部 · 来自 K 个源`。

**同名判定**（`normalizeTitle`）：全角/半角括号、`【】`、多余空格、
分隔符 `·・‧•ー-–—`、冒号都视为相同。
实测检索「狐妖小红娘」：**119 条 → 合并为 47 部**，
其中「狐妖小红娘」有 8 个源、「镜花缘篇」有 10 个源。

> 只在**显示层**合并，后端返回的数据结构没变；想恢复按源查看时把
> `merge_duplicates` 打开即可让后端也参与合并（那是另一套扁平结构，两者不冲突）。

### 关于 mp4：为什么需要转封装

国内动漫资源站**清一色用 HLS（m3u8）播放**——我实测了 30 个资源接口，**没有任何一个提供 mp4 直链**。
m3u8 本身不是视频文件，而是分片清单（`.ts` 分片）。本程序的处理方式：

```
m3u8 清单 → 并发下载 .ts 分片 → 缺失分片自动补下（带 Referer 重试，≤5% 可容忍）
          → 检测到 ffmpeg：转封装为 .mp4（-c copy，不重编码，无损且只需零点几秒）
          → 没有 ffmpeg：直接拼接为 .ts（可播放，兼容性略差）
```

* **转封装不是重新编码**：分片实测是 H.264 + AAC，mp4 容器可直接承载，所以速度极快（实测 192 分片 / 67 MB 只用 0.4 秒）；
* ffmpeg 放 `tools/ffmpeg.exe` 即自动启用（也可放系统 PATH）；一键安装：Web「设置 → 外部依赖」，或
  `.\.venv\Scripts\python.exe tools\fetch_ffmpeg.py`；
* 如果源站直接给的是 **mp4/mkv/flv 直链**，程序会走直链下载（支持 `Range` 断点续传），不做任何转换；
* 资源站给的是分享页（如 `share/xxx`）时，程序会进页面解析 m3u8；确实解析不到就直接报错，
  不会把网页当成视频存下来。

其他要点：
* 分片多线程下载，支持 AES-128 加密流解密；
* 每个任务可暂停/继续/取消，进度、速度、分片数通过 Socket.IO 实时推送到界面；
* 结果列表会标注「直链可下载 / 仅分享页」，方便挑能下的源。

### 任务管理与清理

* 任务页按钮：**全部暂停**、**全部继续**、**清空排队**（取消并移除所有排队/暂停任务，不删已下载文件）、
  **清理空文件夹 / 旧 .ts**、**清理已结束**（清掉完成/失败/取消记录）、
  **全部删除**（删除**所有**任务记录，进行中的会先取消；**磁盘上的视频文件不动**）、**打开目录**；
* **任务按番剧分组**，组头显示集数、各状态计数、总大小、整体进度，可**点击左侧 ▾ 收起/展开**；
  组头还带整部番剧的「暂停 / 继续」按钮；
* 组内排序：**未完成的排前面，已完成的排最后**；番剧之间「还有活干的」排前面；
* **重启不丢队列**：启动时会从数据库把仍处于「排队中」的任务重新装回内存队列继续下载，
  日志会打印「已从数据库恢复 N 个排队任务」；上次退出时正在下载的任务标记为「程序重启，任务中断」；
* **临时分片**放在 `downloads/.tmp`，取消任务不会留下半成品视频；
  设置页的「清理临时文件」可回收空间（实测一次清掉 **642 MB** / 2759 个分片文件）；
* **不会留下空文件夹**：目录只在真正写文件时创建；程序启动时会自动清理空目录；
* **旧的 .ts 会自动清理**：同名视频已是 mp4 时，遗留的 .ts（早期没装 ffmpeg 时生成）
  与空的 `.part` 断点文件都会被清掉（实测释放 64 MB）；
* **没有「已下载就跳过」的规则**：点了下载就下载，**同一集重复下载会覆盖原文件**。
  剧集列表里所有集一视同仁（默认全部勾选），不会出现"某些集点了没反应"的情况；
* 若媒体库里残留了「文件已删但记录还在」的条目，点「清理失效记录」一键清掉。

### 广告源处理（两道检测 + 自动排序）

盗版资源的广告有两种形态，**必须用两种手段分别查**：

| 形态 | 例子 | 会改变时长吗 | 用哪道通道 |
| --- | --- | --- | --- |
| **插播广告片 / 内容残缺** | 片头多一段别的片子；只有半集 | ✅ 会 | **① 时长通道** |
| **叠上去的字幕广告** | 「本片由 41905.com 赞助发布　主营：棋牌 体育 真人娱乐 电子 捕鱼」 | ❌ **不会** | **② 画面文字通道** |

字幕广告是**压进画面像素**的，所以文字层扫描（接口 JSON / m3u8 注释）扫不到 ——
只能**看画面**。而它又不改时长，所以时长对比也测不出来。**单跑任一条都会漏。**

剧集面板的 **`🛡 广告体检`** 按钮会**两条通道一起跑**，跑完自动排序：

```
① 时长通道：并发读取各源该集的 m3u8 总时长，以「众数」为基准
             比常见片长多 ≥20s → 疑插播广告；少 ≥20s → 疑内容残缺
② 文字通道：各源只下载开头 20 秒的分片（自动处理 AES-128 解密）
             → ffmpeg 抽帧 → RapidOCR 识别画面文字 → 匹配广告关键词
             → 检测完**自动删除**临时分片与帧
```

实测（同一集的时长对比）：

```
源          时长        偏差       判定
金鹰资源    1500.5s     ±0.0s     正常          ← 众数基准
极速资源    1500.5s     ±0.0s     正常
暴风资源    1526.1s    +25.6s    ⚠ 疑似插广告（多出 25 秒）
量子资源    1193.4s   -307.1s    ⚠ 疑似残缺（只有一半）
```

实测（文字通道，OCR 原文）：

```
⚠  0s  腾讯动漫AC.QQ.COM…本片由41905.com赞助发布 主营：棋牌体育真人娱乐电子捕鱼 备案编号：19040731506
⚠ 10s  本片由41905.c0m赞助发布 主营：棋牌体育真人娱乐电子捕鱼
   18s  小红#原作：小新（夏天岛工作堂）        ← 正片字幕，正确未误报
→ 检测到广告文字（4 帧命中）: 赞助、本片由、主营、棋牌、捕鱼、真人娱乐
```

**体检完会自动重排**（无需手动操作）：

* 判定有问题的源 → 自动写 `ad_flag` 并**移到列表最后**；
* `ad_kind` 区分原因：`text`（字幕广告）/ `ad`（插播）/ `incomplete`（残缺），
  列表徽章与备注里能直接看到；
* 其余源保持原有相对顺序；
* 重排结果**持久化**（数据库 `ORDER BY ad_flag, sort_order`），下次打开依然生效；
* 全程**流式返回**，右下角作业面板逐个源刷新进度（含每条命中依据），跑完立刻重排。

#### 使用建议（重要）

**时长通道要准，关键是各源比的是「同一集」。** 所以：

1. **先在剧集面板点选某一集**（例如第 10 集），再点「广告体检」
   —— 这样各源都会去取第 10 集，对比才有意义；
2. 不指定集数时退化为「各源的第 1 集」，此时**只有恰好都有第 1 集的源参与对比**；
   少于 3 个源就直接说明「不足以做时长对比」，**不会硬下结论**；
3. 程序还有一道**跨度安全阀**：若同一集各源时长跨度 > 90s，说明它们给的
   其实不是同一版本，这时**不做时长判定**并在报告里写明原因
   —— 宁可不下结论，也不误标一堆正常源为广告源；
4. 报告开头会写明**实际比对的是哪一集、多少源参与、多少源因没有这一集而跳过**。

> **为什么不用中位数**：实测同一集在各源之间本来就有一两分钟编码差异，
> 「中位数 ±15s」一刀切会把十几个正常源全判成插广告（实测踩过：19 个源误标 15 个）。
> 改用**众数**（最多源给出的那个时长 = 大家都认的片长）后就准了。

#### 只有一个按钮

| 按钮 | 跑什么 | 19 个源耗时 |
| --- | --- | --- |
| **`🛡 广告体检`** | 两条通道一起（时长 + 画面 OCR） | 约 4~5 分钟 |

早期还有一个「仅时长（快）」按钮（只跑时长、不做 OCR，约 17 秒），
但它**查不到字幕广告**，容易让人误以为「体检过了就是干净的」，已经移除。
两条通道互补，就不再提供只跑一条的入口。

#### 标记清理规则（重要）

体检不只会**加**标记，也会**清**标记 —— 否则历次体检的结论会不断累积。
实测踩过：因为只加不清，19 个源里积到 17 个被标广告，其中有些备注还写着「正常」。

规则如下（非对称，避免丢结论）：

| 本次情况 | 对已有标记的处理 |
| --- | --- |
| 本次**检查了**且判定正常 | **清掉**旧标记（它已经没问题了） |
| 本次**检查失败 / 无匹配 / 跳过** | **保持原样**（没有新结论，不能凭旧数据删） |
| 本次**只跑时长**（快档），源有 `text` 标记 | **保留** —— 字幕广告只有画面 OCR 能发现，<br>时长正常不代表没字幕广告 |
| 本次**跑了文字通道**，源无字幕广告 | 按本次结论处理（该清就清） |

所以：**快档不会误清字幕广告的标记**；而完整体检才是最权威的一次结论。

#### 画面 OCR 的依赖

文字通道用 **RapidOCR**（`rapidocr-onnxruntime`）—— 自带中文模型、纯 Python 推理，
不需要额外下模型、也不依赖系统 OCR 或桌面会话。

* 依赖已加进 `requirements.txt`（不想要可以注释掉）；
* Docker 里另需 `libgomp1` / `libglib2.0-0` / `libgl1`（已在 Dockerfile 补上）；
* Windows 上 `onnxruntime` 需要 **VC++ 运行库**（`vcruntime140.dll` 等）。
  缺了会报 `DLL load failed`，装一次微软官方的 `vc_redist.x64.exe` 即可；
* **OCR 不可用时程序会明确报错**，而不是静默地把所有源都判成「没广告」
  —— 那种假阴性比报错糟糕得多。命令行可单独自检：

```bash
.venv\Scripts\python.exe tools\ad_detect.py --check-ocr
# OCR 可用（引擎：RapidOCR）
```

命令行也能单独检测某个源或本地文件：

```bash
# 某源某番（自动解析第 1 集）
.venv\Scripts\python.exe tools\ad_detect.py --source-id 110 --keyword 海贼王 --seconds 20
# 本地已下载的视频
.venv\Scripts\python.exe tools\ad_detect.py --video "downloads\狐妖小红娘\第02集.mp4"
```

#### 手动标记

想推翻自动判定时，点某行的 **🚩 旗标按钮**手动标记/取消，标记的源同样会立刻排到最后；
顶部 **「广告源排最后」** 可一键归并。

* 行首出现徽章（**含广告** / **疑似残缺** / **文字广告**），整行有淡琥珀色渐变底；
* 标记状态持久化；所有源列表都是 `ORDER BY ad_flag, sort_order`
  （**数据库层面保证异常源永远在后面**，不只是界面排序）；
* 再点一次旗标即取消标记；
* 检索优先级随之改变：异常源排在最后 → 结果列表里它的分组也在最后。

> 两道通道都只能发现「时长异常」或「画面有广告文字」。
> 若某源是**等长替换**（把一段正片换成广告、总时长不变且画面无文字）则都测不出来，
> 这种情况用旗标手动标记即可。单集判定可能有个别误差，误判就点旗标取消
> （取消后不会再被自动标记，除非下次体检再次判定异常）。

### 源排序（一键排序 / 质量分 / 下载时选源）

「动漫源」页顶部有一排**一键排序**按钮，不用一个个拖：

| 按钮 | 排序依据 |
|------|----------|
| **智能排序** | 质量分（0~100），见下 |
| **可用优先** | 能用的在前，有报错的沉底 |
| **命中最多** | 累计检索命中条目数多的在前 |
| **启用优先** | 已启用的在前 |
| **名称** | 按名称排序（此模式**不受广告标记影响**，否则名字排序会被打乱） |
| **广告置顶** | 把标了「含广告/残缺」的源移到**最前**，方便集中处理/逐个删掉 |
| **默认顺序** | 恢复为内置源的原始顺序 |

排序结果**物理写入 `sort_order` 并持久化**，不是只改界面。

#### 质量分怎么算

四项独立相加，互不掩盖：

| 项 | 满分 | 依据 |
|----|------|------|
| 可用性 | 40 | 测活状态 + **置信修正**后的成功率 `(ok+1)/(ok+fail+2)`。用置信修正而不是 `ok/(ok+fail)`，是为了避免"只测过 1 次成功"就拿到满分——样本越多越接近真实值。只有失败记录时直接给 0 |
| 内容量 | 25 | 累计检索命中数，对数缩放（100 条命中≈满分），避免大站碾压一切 |
| 响应速度 | 20 | 最近一次测活耗时：≤300ms 满分，≥5s 归零 |
| 干净度 | 15 | 标了「含广告/残缺」的源**整项归零**（质量分直接 0） |

**内容量和响应速度需要先采样**：点工具栏的 **`⏱ 质量采样`**（会问一个抽样关键词），
程序会并发给每个源测活 + 检索一次，把耗时与命中数写入数据库。不采样时这两项为 0，
智能排序会退化成只看成功率。采样 13 个源约 8~10 秒，进度显示在右下角作业面板。

切到「智能排序」后，每行会显示质量分徽标（绿≥70 / 橙≥40 / 红<40）。

#### 下载时选源（只选一个，失败不自动回退）

打开某部动漫的剧集面板，顶部有 **`下载源`** 一栏：

* 列出所有**已启用**的源，当前源高亮；点另一个源会**在该源上重新检索这部番剧**
  并刷新剧集列表（同一部动漫在不同源的集数/清晰度可能不同）；
* 下载时**只从选中的那个源解析**，不做静默换源 —— 换源会换掉清晰度/字幕，
  静默替换比直接报错更难排查；
* 右侧 **`失败自动换源`** 开关默认**关闭**。开启后，解析不出视频地址时才会
  自动换其它源重试同一集（最多 3 次）。

> 之所以默认关闭：这个源可能只是"能看不能下"（分享页），但用户选它往往是有意的
> （比如清晰度更好）。自动换掉之后画面变了却没有任何提示，属于"帮忙帮出问题"。

## 七、常见问题

**Q：双击 `启动.bat` 提示“没有找到 python 命令 / Python was not found”？**
说明系统里没有可用的 Python（PATH 里的 `python` 往往是微软应用商店的占位程序，不能真正运行）。
优先检查本目录是否存在 `.venv\Scripts\python.exe`——**只要存在就会被直接使用，完全不需要系统 Python**。
若确实没有 `.venv`：
1. 装一个 Python 3.10+（安装时勾选 *Add python.exe to PATH*）：<https://www.python.org/downloads/windows/>，再双击 `启动.bat`；
2. 或把别处已建好的 `.venv` 整个目录拷进本目录；
3. 或直接用任意 python.exe 启动：`<你的python.exe> run.py`。

**Q：某些源检索没结果？**
在「动漫源 → 测试」看报告：
* MacCMS 源会逐个接口报告「条目数 / 剧集数 / 是否 m3u8 直链」，直接看出是接口挂了还是该条目没资源；
* 通用/网页源会分「检索 / 剧集 / 视频地址」三步报告，多数情况是选择器或链接正则需要微调，
  也可以先用「自动探测」生成草稿。

**Q：某个资源站突然搜不到了？**
资源站接口会更换域名。到「动漫源 → 编辑」把接口地址换成新的即可；也可以一次填多个备用接口
（`apis` 字段），程序会按顺序自动切换。失效的源取消勾选就行，不影响其它源。

**Q：内置源一个都不见了 / 想恢复默认源？**
内置源是幂等补齐的：删掉 `data/moanime.db` 后重启，会自动重新写入全部内置源
（同名源不会被覆盖）；也可以点「导入」粘贴 `moanime-sources.json`。

**Q：下载下来是 `.ts` 而不是 `.mp4`？**
说明没检测到 ffmpeg。在「设置 → 外部依赖 → 一键下载安装」装好后重新下载即可
（也可在设置里关闭“转封装为 mp4”）。

**Q：站点有反爬 / 需要 Cookie？**
在源编辑的「高级 / JSON」里填 `headers`，例如
`{"Referer": "https://站点/", "Cookie": "cf_clearance=..."}`；也可在设置里配代理。

**Q：浏览器打开 `http://127.0.0.1:8848/` 显示“拒绝连接”？**
说明服务没在 8848 上跑。常见三种情况，按顺序排查：
1. **服务没启动**：双击 `启动.bat`，看窗口里打印的 `Web 界面：http://127.0.0.1:xxxx` 是哪个端口，以它为准；
2. **端口被改过**：`data/settings.json` 里的 `web_port` 就是实际端口（网页「设置 → 界面与服务」也能改）。
   端口被别的程序占用时，程序会**自动顺延到下一个可用端口**，注意看窗口提示；
3. **已经有一个实例在跑**：启动器会提示“检测到服务已经在运行”并直接打开浏览器，不会重复启动；
   停止服务请运行 `.\停止.ps1`。

**Q：服务跑着跑着自己退了 / 关掉窗口就没了？**
前台模式（`启动.bat`）的服务生命周期就是这个黑窗口；想让它在后台常驻，用 `.\后台启动.ps1`。
日志在 `logs/app.log`（运行日志）与 `logs/service.err.log`（后台模式的控制台输出）。

快速排查命令：
```powershell
Get-NetTCPConnection -LocalPort 8848 -State Listen     # 有输出=在跑；无输出=没跑
```

**Q：想让局域网里的其他设备访问？**
`.\.venv\Scripts\python.exe run.py --host 0.0.0.0`（命令行给的参数只影响本次运行，不会写进设置；
要永久生效请在网页「设置」里改“监听地址”。）

**Q：数据存在哪？**
`data/moanime.db`（源、任务、历史）、`data/settings.json`（设置）、`logs/app.log`（日志）。
删除数据库会重置所有源与任务记录。
